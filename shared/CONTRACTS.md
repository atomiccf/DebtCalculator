# Контракты расчётов

`src/contracts` экспортирует схемы `.parse(unknown)`, типы запросов и ответов,
а также функции `calculate*Request`, которые проверяют запрос и вызывают
прикладные сервисы из `src/services`. HTTP-обработчики проверяют JSON теми же
схемами и вызывают сервисы напрямую. Клиент проверяет форму перед `fetch`.
Неизвестные поля отклоняются, чтобы
новый параметр не терялся молча. При ошибке проверки API возвращает HTTP 400 и
`{ error, issues: [{ path, message }] }`; путь документа — `documents.1.debt`.
Тот же формат применяется к ошибкам JSON, ограничениям расчёта, отсутствующим
маршрутам (404), превышению размера запроса (413) и неподдерживаемой кодировке
(415). Непредвиденные ошибки возвращают 500 без внутренних подробностей.
Пакет проверяется целиком до первого расчёта.

Все транспортные даты — существующие календарные даты `YYYY-MM-DD`.
Объекты `Date`, временные метки и строки с часовым поясом в запросах запрещены.
Момент обновления справочника (`updatedAt`) остаётся временной меткой.
Денежные значения — числа BYN с точностью до копейки; ставки — конечные
неотрицательные числа. Строки вместо чисел не преобразуются. Для пени `rate` должна
быть строго больше `0`; нулевая годовая ставка допустима в расчётах по ст. 366.

| Сценарий | Обязательные поля |
| --- | --- |
| Любая пошлина | `courtType`, `plaintiffType`, `caseType`, `date` обращения |
| Имущественное требование, спор о качестве, приказ | Дополнительно `amount > 0` |
| Жалоба | Оспариваемая `amount` либо `originalCaseType` |
| Экономическая жалоба без суммы | Если исходный тариф зависит от суда — `originalCourtLevel` |
| Административная жалоба (включая исходное требование) | `administrativePenalty: fine/other`; для `fine` также `fineAmount > 0` |
| Пеня | `debt`, `startDate`, `endDate`, явная дневная `rate` |
| Статья 366 | `debt`, `startDate`, `endDate`, `calculationBasis`, явный `hasPenalty` |
| Статья 366: оплата, решение, исполнительная надпись | Дополнительно `rateDate`, `dayCount` |
| Статья 366: несколько лет | Явный `dayCount`, в том числе для предварительного расчёта |
| Статья 366 с неустойкой | `statutoryException: true` |
| Любой пакет | Непустой `documents`; у каждой строки `name`, `debt`, `startDate`, `endDate` |

Оба маршрута пени принимают только явно переданный дневной размер пени `rate > 0`.
Значения по умолчанию нет. Поля `annualRate` и `dayCount` отклоняются даже при
наличии дневной ставки. Годовая арифметика остаётся в общем ядре для ст. 366;
в её запросах ставка задаётся полем `refinancingRate` либо выбирается из справочника.

Суды: `common`, `economic`, `appellate_economic`, `supreme_economic`.
Заявители: `individual`, `organization`, `ip` (последний в экономических судах).
`ip` больше не является видом суда. Общий суд допускает также организации;
экономический — также физических лиц. Виды требований проверяются по суду
и типу заявителя.

## Каталог льгот и расчётные освобождения

`discounts`, `getDiscountById` и `getDiscountsForCourt` экспортируют неполный
справочный каталог по юридической сверке редакции 2026 года. Каждая запись
имеет `kind: reference-only`. `courtTypes`, `caseTypes` и `appliesTo` используют
общие типы `CourtType`, `DutyCaseType` и `PlaintiffType`; `appliesTo` теперь
содержит массив конкретных типов заявителя вместо строки `both`.
Записи и их поля доступны только для чтения в TypeScript.

В каталоге оставлены основания, подтверждённые в `LEGAL_REVIEW.md`: алиментное
требование (подп. 1.1.2 ст. 285) и апелляция физического лица по расторжению
брака без раздела имущества (подп. 1.3.4). Прежние неподтверждённые записи и
произвольные категории `all`, `damage`, `quality_dispute` и другие удалены.
Стабильный ID алиментной записи `1.1` сохранён; правовое основание находится
в `articleRef`, поэтому ID не следует интерпретировать как номер нормы.

`getDiscountsForCourt(courtType, caseType)` фильтрует только по суду и виду
требования. Он не проверяет заявителя, исходное требование (`originalCaseTypes`
в записи), сумму, дату или другие юридические факты и не подтверждает право
на освобождение. Пустой результат также не означает отсутствия права на льготу.
Каталог не является историей редакций и не выбирается по дате обращения.

Автоматические освобождения применяются отдельно: `rules2026.ts` задаёт ноль
для алиментного требования; `isDutyIndividualAppealExempt` из
`dutyRequirements.ts` проверяет апелляцию физического лица в общем суде по
алиментам или одному из поддержанных видов развода. В расчёте апелляции
это освобождение действует без оспариваемой суммы. Добавление справочной
записи не изменяет расчёт, а совпадение в каталоге не заменяет эти проверки.

## Дополнительные параметры расчёта

Для жалобы `originalCaseType` не может быть другой жалобой. Имущественное
исходное требование требует оспариваемой суммы. `isRepeated` передаётся
для повторного брака, в том числе в исходном требовании. Отдельный вид
`contract_dispute` не подменяет общий неимущественный иск.

`dayCount`: `360`, `365`, `366` (числа), `start-year`, `end-year`, `actual/actual`.
Основания ст. 366: `payment`, `judgment`, `executive-endorsement`, `estimate`.
`rateDate` не подменяется датой окончания для юридических оснований.
В `estimate` пропущенная дата ставки заменяется концом периода с предупреждением.
Необязательная `refinancingRate` задаёт явную ставку; источник отражается в ответе.
Параметры ставки, основания, неустойки и делителя задаются на весь пакет;
переопределения в строках отклоняются.

Пример запроса на `/api/interest/calculate-366-multiple`:

```json
{
  "documents": [{ "name": "Договор", "debt": 10000, "startDate": "2026-05-01", "endDate": "2026-05-31" }],
  "calculationBasis": "judgment",
  "rateDate": "2026-06-01",
  "dayCount": "actual/actual",
  "hasPenalty": false
}
```

Ответ сохраняет суммы и добавляет `methodology`, `rulesVersion`, `rules`,
`referenceData` и `warnings`. `rules` содержит выбранную версию, источник,
проверенные нормы и известные границы действия редакции. Снимок справочной
записи содержит дату выбора, фактически использованное значение, `dateFrom`,
известную `dateTo`, акт, источник и версию справочника; для проверенных записей
также `verifiedOn`. Отсутствующая `dateTo` означает, что окончание действия
не установлено, а `supportedThrough` ограничивает покрытие встроенного снимка.
Это разные даты. Строка ответа ст. 366 и
ответ пошлины также сохраняют `input` для проверки полноты передачи условий.
У пакетов справочники сохраняются в каждой строке: в предварительном режиме
даты выбора ставки могут различаться. Общий `referenceData` пуст, чтобы не
выдать данные первой строки за данные всего пакета. Предупреждения ст. 366
агрегируются на уровне пакета и показываются клиентом.

Для явной годовой ставки `origin: input`, `source` и `version: user-input`,
`dateFrom`/`dateTo: null`: пользователь передал значение на `selectedOn`,
но не предоставил подтверждённый период действия. Дневная ставка сохраняется
в `referenceData.dailyRate` вместе с периодом её применения и источником
`user-input`. Договорный срок действия отдельно не устанавливается.

Начало периода — установленный первый день просрочки; оба края включены.
Округление — до копейки, половина вверх. Итог — точная сумма округлённых строк.
Снимок тарифов пошлины поддерживает обращения **2026-07-01 — 2026-12-31**;
первое полугодие и другие годы отклоняются: июльскую редакцию нельзя применять
к ним автоматически. Приказное производство: меньше 100 БВ — 2 БВ,
от 100 включительно до 300 исключительно — 5 БВ, от 300 включительно — 7 БВ.
Встроенные справочники не заменяют онлайн-проверку актуальности.

## Справочные HTTP-маршруты

`GET /api/rates/base-value`, `/api/rates/refinancing`, `/api/rates/current`
принимают необязательную календарную `date`; без неё используется день
`Europe/Minsk`. У обоих маршрутов ставки НБРБ ключ кэша — именно дата запроса,
TTL — один час, таймаут запроса и чтения тела — пять секунд.
HTTP-статус, структура, конечное неотрицательное значение и календарная дата
каждой записи проверяются. Запись выбирается по дате действия, независимо от
порядка ответа. Будущие запросы ставки отклоняются. Некорректные ответы и
резервные значения не попадают в кэш успешных ответов.

Ставка возвращается с `requestedOn`, фактической датой начала `date`, известной
`dateTo`, `source`, `version`, `act`, `fallback` и `warnings`; онлайн-ответ также
содержит `fetchedAt`. При сбое выбирается встроенная запись на ту же дату,
а не сегодняшняя ставка; `fallback: true` и предупреждение обязательны.
Строка `fallback` вместо даты больше не возвращается. За границами встроенного
снимка при отсутствии ответа НБРБ возвращается ошибка, без подстановки.
`/current` сохраняет прежние числовые поля и дополнительно отдаёт выбранные
записи в `referenceData`.

Справочные GET-маршруты предназначены для отдельного просмотра данных.
Расчётные POST-маршруты синхронно выбирают встроенные записи в прикладном
сервисе, явно передают значения ядру и сохраняют эти же записи в результате.
Клиент показывает данные результата и не заменяет их свежей онлайн-ставкой.
Порядок обновления и поддерживаемые версии описаны в
[REFERENCE_DATA.md](REFERENCE_DATA.md).

## Проверка

Из корня: `npm run test:contracts -w shared`, `npm run typecheck -w shared`,
`node node_modules/typescript/bin/tsc -p client/tsconfig.json --noEmit`.
HTTP-тестам требуется локальное соединение с временным портом на `127.0.0.1`.
Полный набор: `npm test -w shared`; без сети: `npm run test:unit -w shared`.
Назначение наборов, удалённые дубли и проверки согласованности каталога льгот
с юридической сверкой описаны в [test/README.md](test/README.md).
