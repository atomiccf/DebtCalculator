# Shared: расчётная библиотека

Библиотека разделяет вычисления и выбор справочных данных. Существующие импорты
из `jurist-calculator-shared` сохранены. Изменения касаются исходников `shared`;
сервер и интерфейс используют общие [контракты](CONTRACTS.md) запросов и ответов.

## Границы ответственности

- `penalty/accrual.ts`: чистые вычисления с явной ставкой и правилом дней в году.
- `calculate/*Courts.ts`: чистые функции `*WithBaseValue` с явной базовой величиной
  и совместимые обёртки, выбирающие величину по дате.
- `referenceData/effectiveRecord.ts`: выбор записи из переданной истории по дате.
- `api/baseValue.ts`, `api/refinancingRate.ts`: встроенные справочники и обёртки.
- `utils`: календарные даты, валидация и точная денежная арифметика.

HTTP, база данных, кэш и обновление справочников относятся к серверу. Чистые
функции не выполняют запросов и не читают часы. Они возвращают одинаковый
результат при одинаковых входных данных. Датированные функции-обёртки без даты
используют текущий календарный день в `Europe/Minsk`.

## Явные правила расчёта

```ts
import {
  calculateAnnualAccrual,
  calculateCommonCourtDutyWithBaseValue,
} from 'jurist-calculator-shared';

const interest = calculateAnnualAccrual({
  debt: 100000,
  startDate: '2023-12-31',
  endDate: '2024-01-02',
  rate: 10,
  dayCount: 'actual/actual',
}); // amount: 82.04

const duty = calculateCommonCourtDutyWithBaseValue(
  { caseType: 'property', plaintiffType: 'individual' },
  45,
  10000,
); // 500 BYN
```

`calculateDailyAccrual` принимает дневную процентную ставку. Для годовой ставки
`calculateAnnualAccrual` требует `dayCount`: `360`, `365`, `366`, `start-year`,
`end-year` или `actual/actual`. Последний вариант складывает доли каждого
календарного года и округляет один раз в конце.

В обеих функциях включены первый и последний день периода. Результат содержит
нормализованные входные данные, сумму, число дней, `rulesVersion`, `rounding`
и `periodIncludes`; годовой результат дополнительно содержит `dayCount`.
При сохранении расчёта приложение должно сохранять результат и использованный
снимок справочников. `rulesVersion` идентифицирует текущий алгоритм, но сама по
себе не предоставляет исполнение старых версий: старую реализацию нужно
сохранять отдельно при последующих изменениях.

## Совместимость и исправленные ошибки

- Имена существующих функций сохранены. После юридической сверки валидация стала
  строже; результат по ст. 366 дополнен датой ставки, основанием и предупреждениями.
- `calculateInterestOnDebt` сохраняет делитель года начала. Дополнительный пятый
  аргумент позволяет явно выбрать другое правило.
- `calculateInterest366` принимает `rateDate`, `calculationBasis`, `dayCount`,
  `hasPenalty`, `statutoryException` и необязательную явную `refinancingRate`.
  Основания: `payment`, `judgment`, `executive-endorsement`, `estimate`.
  Для юридического основания обязательны дата ставки и правило делителя.
  Для нескольких лет правило делителя обязательно в любом режиме. В одном году
  предварительный расчёт без правила использует календарный делитель и предупреждение.
  В режиме `estimate` без `rateDate` дата окончания используется только для оценки.
  Для пакетного расчёта общие параметры передаются вторым аргументом.
- Ставка дневной пени теперь обязательна: значения 0,1% в день нельзя считать
  универсальной ставкой, установленной законом.
- Обратные периоды, несуществующие даты, строки вместо чисел, `NaN`, бесконечность,
  отрицательные ставки и неположительные долги отклоняются. Ставка `0` допустима.
- Денежные входы задаются числами BYN с точностью до копеек. Слишком большие суммы,
  теряющие точность при преобразовании в публичный `number`, отклоняются.
- Внутри используются целые числа `bigint` и десятичные дроби. Округление — до
  копеек, половина вверх; результаты совместимы с JSON.
- Итог по документам равен сумме округлённых строк. В расчёте пени со сменой
  ставок итог также равен сумме округлённых периодов.
- История ставок должна покрывать начало периода; дубли дат отклоняются,
  порядок входной истории не важен, будущая ставка не применяется задним числом.
- `getDiscountsForCourt` фильтрует также тип дела; необязательный третий аргумент
  ограничивает результат типом заявителя, четвёртый задаёт стадию дела.
  Каталог льгот заменён проверенным подмножеством; старые ошибочные ID удалены.
  Автоматически учтены явно поддержанные алиментные требования и апелляция,
  апелляция по расторжению брака без раздела имущества. Остальные льготы требуют
  отдельной проверки обстоятельств и применения.

Строковые даты — строго `YYYY-MM-DD`, объекты `Temporal.PlainDate` — календарь
ISO. Для переданного объекта `Date` берутся компоненты UTC, чтобы результат не
зависел от часового пояса машины. Для юридически значимой календарной даты
предпочтительна строка.

## Справочники и границы проверки

Встроенные истории заморожены. Даты раньше первой записи вызывают ошибку,
вместо подстановки значения из будущего. `getEffectiveRecord` поддерживает
необязательный включительный `dateTo`; интервалы без подходящей записи дают ошибку.
Без `dateTo` последняя известная запись действует дальше: библиотека не проверяет
актуальность справочника в сети и не гарантирует ставки будущих периодов.

Значения и даты ставок с 23.01.2023 сверены 20.10.2026 с официальной таблицей
МНС: https://nalog.gov.by/reference/penalty_rate/. Исправлены записи за 2023–2024
годы и добавлена ставка 9,25% с 01.06.2026. Для проверенных записей сохранены
`source` и `verifiedOn`; поле `act` ссылается на таблицу без неподтверждённых
номеров постановлений. Более ранняя история и справочник базовой величины
перенесены без полной повторной проверки.

Тарифы, льготы и условия ст. 366 сверены с официальными источниками. Исправлены
подтверждённые расхождения. Результат сверки, источники и оставшиеся ограничения:
[LEGAL_REVIEW.md](LEGAL_REVIEW.md). Датированные функции пошлин поддерживают
снимок тарифов 2026 года; другие годы отклоняются вместо применения текущих
коэффициентов задним числом. Чистые функции с явной БВ также используют эту
редакцию тарифов. Метаданные снимка доступны как `DUTY_RULES_2026`.

Для жалобы без оспариваемой суммы обязателен `originalCaseType`; если исходный
экономический тариф зависит от суда, нужен `originalCourtLevel`. Общий
неимущественный иск и договорный спор (`contract_dispute`) разделены. Для
административной жалобы задаются `administrativePenalty` и при штрафе `fineAmount`.
Точные стыки 100/300 БВ приказного производства пока отклоняются до подтверждения
границы тарифа. Расчёт относится к одному самостоятельному требованию.

`startDate` — уже определённый первый день просрочки, а не дата, когда обязательство
ещё можно было исполнить своевременно. Рабочий календарь и перенос сроков не
рассчитываются автоматически. Предупреждения `warnings` по ст. 366 необходимо
показывать пользователю; календарный делитель сам по себе не подтверждает
применимость выбранной методики к конкретному договору.

Сервер проверяет запросы общими схемами и вызывает прикладные сервисы из
`src/services`, без собственных формул и подстановки дневной ставки.
Функции `calculate*Request` сохранены как обёртки проверки и вызова этих сервисов.
Пеня принимает только дневную ставку; годовые проценты рассчитываются по ст. 366.
Клиент использует те же схемы,
собирает параметры исходного требования, взыскания и ст. 366, отображает
методику, справочные данные и предупреждения.

## Проверка

Из папки `shared`:

```text
npm test
npm run typecheck
```

Тесты выполняют актуальные TS-исходники в памяти через установленный TypeScript
и встроенный `node:test`, без сборки и дополнительных зависимостей. Проверка
типов также компилирует исходники сервера без генерации файлов, направляя импорт
`jurist-calculator-shared` на текущие исходники библиотеки.
