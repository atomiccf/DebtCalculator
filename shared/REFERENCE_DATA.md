# Снимки справочников и правил

Дата дополнения: **13.11.2026**. Выбор делает прикладной сервис до вызова ядра.
В результат и клиент попадает выбранная запись, без повторного поиска.
Сохранённый результат вместе с `rules`, `referenceData`, `input` и методикой
составляет снимок расчёта. Онлайн-обновление не изменяет сохранённые расчёты.

## Поддержка

| Объект | Версия / покрытие | Источник |
| --- | --- | --- |
| Пошлины | `by-nk-2026-review-2026-10-20-v2`; обращения 01.07–31.12.2026 включительно | НК, приложения 13, 15; ст. 285, 287, 288; источники в [юридической сверке](LEGAL_REVIEW.md) |
| БВ | `by-base-value-history-2026-11-13`; 01.01.2019–31.12.2026 | Акт указан в каждой записи; [МНС о БВ 45 BYN с 01.01.2026](https://nalog.gov.by/news/33270/) |
| Ставки | `by-refinancing-history-2026-11-13`; 21.12.1999–13.11.2026 | Акт в каждой записи; [таблица МНС](https://nalog.gov.by/reference/penalty_rate/) повторно проверена для записей с 2023 года; более ранние записи перенесены без полной повторной проверки |
| Начисление | `2.1.0` | `penalty/accrual.ts`: включительные дни, точная арифметика, округление half-up |
| Ст. 366 | `by-gk-366-review-2026-10-20+accrual-2.1.0` | [ГК, ст. 366](https://etalonline.by/document/?regnum=hk9800218); юридические факты и делитель передаёт пользователь |

НК до 01.07.2026 и с 01.01.2027 не поддержан. Июльская редакция не объявляется
редакцией на весь 2026 год. Новые редакции не подбираются по принципу «последняя
известная». Чистые функции с явной БВ исполняют конкретный тарифный снимок,
но не устанавливают его применимость на историческую дату.

Даты `dateFrom`/`dateTo` — включительные даты действия. Конец исторической
записи определяется как день перед началом следующей. Для последней записи
юридическая дата окончания может быть неизвестна. `supportedThrough` — предел
покрытия встроенного справочника; он не означает прекращение действия акта.
Последняя ставка не распространяется на будущие даты без обновления снимка.
За пределами покрытия встроенных данных нужен обновлённый справочник либо
явно заданная пользователем ставка. Явная ставка не подтверждает юридический
период её действия: в ответе даты этого периода равны `null`.

Приказное производство: меньше 100 БВ — 2 БВ; 100 включительно — меньше 300 БВ —
5 БВ; от 300 включительно — 7 БВ. Контроль при БВ 45 BYN: 4499,99 → 90;
4500 → 225; 13 499,99 → 225; 13 500 → 315. Это тарифные ступени, а не проверка
допустимости конкретного требования к рассмотрению в приказном порядке.

Исторические редакции ГК автоматически не определяются. Версия ст. 366
обозначает проверенную методику, а не каталог всех исторических редакций.
Чистая арифметика работает с явной ставкой и вне справочного покрытия.
Остальные юридические ограничения перечислены в [LEGAL_REVIEW.md](LEGAL_REVIEW.md).

## Обновление

1. Проверить официальный акт, дату вступления в силу, переходные положения
   и область применения. Сохранить прямой источник и дату проверки. Новое
   значение справочника не подтверждает новую редакцию тарифов.
2. Добавить запись в `api/baseValue.ts` или `api/refinancingRate.ts`, задать
   источник и версию снимка, обновить `supportedThrough` после сверки. Не
   менять дату начала старой записи ради поддержки новой даты. Исторические
   `dateTo` закрываются перед следующим изменением автоматически.
3. Для изменения тарифов сохранить прежнюю реализацию и добавить отдельный
   снимок с уникальной версией и непересекающимся интервалом. Зарегистрировать
   полную редакцию (`DutyEdition`: метаданные `rules` и функция `calculateUnits`)
   в `dutyEditions` из `calculate/dutyEditions.ts`. Метаданные `dutyRulesHistory`
   получаются из этого реестра автоматически; общий алгоритм менять не нужно.
   Реализация получает проверенные факты и точные внутренние единицы, возвращает
   сумму без округления до копеек. Границы поддержки менять только после проверки
   содержания, а не смены года. Обёртки без даты с явной БВ остаются привязаны
   к редакции 2026; для другой версии использовать `calculateDutyWithRules`.
4. Для изменения начисления повысить версию алгоритма. Сохранить реализацию
   прежней версии, если требуется повторное исполнение старых расчётов.
   Сами метаданные не обеспечивают исполнение удалённой реализации.
5. Проверить день до изменения, сам день и день после; для тарифов — суммы
   на порогах и на копейку ниже/выше, оба суда, одиночный и пакетный расчёт.
   Проверить совпадение значений ядра, метаданных и отображения.
6. Выполнить `node --test shared/test/referenceData.test.cjs`,
   `npm test -w shared`, `npm run typecheck -w shared` и проверку типов клиента,
   обновить эту таблицу и юридическую сверку. Известное расхождение каталога
   льгот и назначение тестов описаны в [test/README.md](test/README.md).

## НБРБ

`NbrbService` хранит только проверенные онлайн-ответы, отдельно для каждой даты
запроса. Дата по умолчанию — `Europe/Minsk`; явная такая же дата использует тот
же ключ. TTL — час, таймаут запроса и чтения тела — пять секунд. Кэш ограничен
256 записями; ошибки, истёкшие значения и резервные записи не кэшируются как
успешный ответ. Даты и ставки проверяются до помещения в кэш; порядок массива
не определяет выбранную запись.

При сбое HTTP, некорректном JSON/значении, таймауте или отсутствии подходящей
записи API выбирается встроенная ставка на **дату запроса**. Ответ содержит
`fallback: true`, предупреждение, фактическую дату действия и источник резерва.
При отсутствии покрытия возвращается ошибка. Будущие даты не подтверждаются
сегодняшней ставкой. Ответ онлайн содержит ссылку на запрос, `fetchedAt` и
версию снимка ответа. `NBRB_API_URL` меняет адрес провайдера, не правила выбора.

Онлайн GET-данные и встроенные данные расчёта имеют разное происхождение;
форма отображает справочник из результата расчёта, без подмены данными GET.
